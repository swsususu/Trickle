附：数据源调研结论（已在本机 Mac16,8 / macOS 27 实测）

CPU：host_processor_info() 读每核 tick 做差值；hw.perflevel0/1.logicalcpu 区分性能核 8 / 能效核 4。无需权限，项目已依赖 mach crate。
GPU：IORegistry IOAccelerator → PerformanceStatistics 的 Device Utilization %、In use system memory，实测可读（当前 53%）。与现有 AppleSmartBattery 读取方式相同。
内存：host_statistics64(HOST_VM_INFO64) 取 active / wired / compressed；kern.memorystatus_vm_pressure_level 取压力等级（1 正常 / 2 警告 / 4 严重），vm.swapusage 取交换。
网络：getifaddrs() 的 if_data.ifi_ibytes/obytes 做差值，排除 lo0、utun*、awdl*、bridge*，避免 VPN 流量重复计数。
CPU / GPU 分项功率：卡片右上角的 W 值在无 root 下只有 SMC 可拿，key 因芯片代际而异，需逐机型验证；拿不到时隐藏该字段而非显示 0。
开销：以上全是内核计数器读取，单次 <1ms，可直接挂在现有 power-tick 定时器上，不新增线程。主窗口成本主要在前端图表渲染，已知主窗口打开时约 19% CPU，新增卡片应复用现有动画开关。
定位提醒：HANDOVER.md 第五节曾建议不做通用监控以免与 exelban/stats 正面竞争。本方案通过「负载 × 功耗」联动和耗电排行扩展，把新数据绑定在电源主题上，保持差异化。
